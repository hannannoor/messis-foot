# Final independent review and disposition

5 November 2026. A fresh read-only reviewer checked the adapter, official scoring functions, split/feature separation, freeze identity, portable runtime and delivery script. The reviewer independently ran 24 focused adapter, benchmark, freeze and tactical tests; all passed. No challenge video, GT or per-frame output was reviewed.

The scientific recommendation was to approve an **opt-in provider-reference experiment**, retaining the frozen model. The complete external target improves on both test matches; local X decreases by 20,717 frames. The inactive coordinate-freezing artifact, slight active-only spell regressions and lower H/A agreement prevent claims of transferable stoppage detection, improved team-only spells or local accuracy. These limitations are prominent in FOUR_GOALS.md, the bundle guide and model/report metadata. The legacy default remains intact. A post-test physical-D gate and retuning on these results were declined.

Three CLI issues were fixed with observed failing-then-passing regression tests: negative reprojection errors, injected dead evidence, and tags retained in an allegedly identical-input baseline. These do not alter the completed real tracking inference. No freeze-protected inference/scoring source changed after final scoring.

The reviewer required staged hash verification, atomic executable replacement and safe partial-install recovery. The initial installer copied directly onto final paths and could strand a partial delivery. It now stages and verifies every copy on the destination volume, atomically moves/replaces files with the executable last, and resumes only exact expected partial files. Unknown/edited content is preserved. The reproduction test failed on the old partial-folder rule, then passed after the fix; a second test verifies unrelated files are preserved. Delivery must additionally pass final installed hash checks.

Two minor development-tool limitations were recorded without changing verified results: acquisition retry can repeatedly resume a checksum-invalid partial download at EOF; and an interrupted held-out checkpoint write can leave malformed JSON. Preserve the completed verified downloads/reports. If either development failure occurs, preserve/rename the invalid partial file before a clean retry; do not refit or reselect the existing freeze. Atomic acquisition/checkpoint improvements are deferred because they do not affect delivered inference or the already verified evidence.

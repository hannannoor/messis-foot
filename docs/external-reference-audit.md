# External IDSSE / Sportec Open DFL reference audit

Audit date: 2026-11-05. Read-only research of external primary documentation and public loader source. No challenge video, tracking, or ground truth inspected; no dataset files downloaded.

## Authoritative facts

The [Bassek et al. primary paper, mirrored in PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC11787359/) states that DFL authorized release under CC BY 4.0. Exact supporting excerpt: “released under a CC-BY 4.0 license with the authorization from the DFL” (16 words). This concerns the dataset, beyond the article's own open-access licence. Attribute Bassek, Rein, Weber and Memmert (2025), DFL, the [original Figshare DOI](https://doi.org/10.6084/m9.figshare.28196177), and [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); identify transformations. Figshare itself was inaccessible to this audit tool; licence confirmation comes from the primary paper, corroborated by the [maintainer mirror](https://huggingface.co/datasets/pysport/idsse-data).

The paper describes official DFL data: Sportec collection, TRACAB Gen5 multi-camera tracking at 25 Hz, and trained analysts creating event data with quality control. It defines BallPossession by the controlling player's team: 1=home, 2=away. BallStatus: 0=inactive, 1=active; referee interruptions are inactive. It does not specify frame-label creation algorithms, uncertainty, loose-ball/flight policy, or an independent possession annotation study. No videos are released. Treat labels as provider reference, not independently human-verified competition possession gold. Event timestamps can require synchronization; the paper's synchronization analysis did not use video ground truth. Optical tracking has projection, occlusion and identity risks.

The [floodlight DFL reader](https://floodlight.readthedocs.io/en/latest/_modules/floodlight/io/dfl.html#read_position_data_xml), the paper's referenced tooling, independently confirms definitions `{1: "Home", 2: "Away"}` and `{0: "Dead", 1: "Alive"}`. It returns position, possession and status as separate objects. No third possession state or BallStatus=2 is defined there. Do not interpret possession=0, possession missing, or an unfamiliar status as a confirmed team or confirmed stoppage. Count raw codes and missing fields before selecting targets; retain raw values and explicit validity masks.

## Loader hazards and leakage controls

The [current kloppy Sportec tracking deserializer](https://raw.githubusercontent.com/PySport/kloppy/master/kloppy/infra/serializers/tracking/sportec/deserializer.py) assigns home if BallPossession equals 1 and away otherwise (lines 364–368 when inspected). Its default for absent possession is 0. Thus missing, 0 and unexpected numeric values can silently become away. Likewise status other than 1 becomes DEAD. Preserve raw XML labels before this coercion. The reader's `only_alive=True` removes frames using BallStatus itself; use `False` when evaluating a state predictor. Missing ball records are also skipped by this reader.

Recommended contract: a strict allowlist of coordinates, team membership and geometric/kinematic features forms X; raw BallPossession/BallStatus and all derived ownership/status fields form y only. Exclude event logs, event outcomes, possession phases, referee decisions, official net time, target-dependent filtering, and target-derived segmentation from inference. Fit scaling, imputation and temporal parameters only on training matches. Verify prediction inputs and serialized models contain no label columns. If comparing possession only on reference-active frames, label that metric as conditional and report all-frame status separately.

Ball flight is an unresolved semantic issue: neither checked primary paper nor reader establishes that team possession always continues through flight, or that flight is always neutral. Height/velocity alone cannot justify rewriting provider labels into a new semantic gold. Preserve provider labels; document the target definition and evaluate transition/flight behavior as a limitation. This dataset cannot directly supervise a separately defined contested/neutral class without additional annotation rules.

## Manifest, split and transfer limits

The [actual mirror file manifest](https://huggingface.co/datasets/pysport/idsse-data/tree/main) and [kloppy provider registry](https://raw.githubusercontent.com/PySport/kloppy/master/kloppy/_providers/sportec.py) agree on J03WMX, J03WN1, J03WOH, J03WOY, J03WPY, J03WQQ, J03WR9. Registry lists first two in competition 000001 and remaining five in 000002. README's J03WPF/J03WQF are inconsistent with files. Pin manifest revision and file checksums in the local acquisition record; do not build acquisition from README IDs.

Recommended fixed development split, selected before results: train J03WOH/J03WOY/J03WPY/J03WMX; validation J03WQQ; final external test J03WR9/J03WN1. Keep each whole match, both halves and all windows, in exactly one partition; do not use random frames. This gives training and final testing one first-division match each, plus a chronological second-division progression. Report each test match and their macro average, in addition to pooled metrics. Never retune on final test.

A match-heldout split is feasible but does not ensure team independence: the registry shows Fortuna Düsseldorf in all five second-division matches. Consider supplementary leave-one-match-out results and a division-heldout stress test. Neither replaces a frozen final test. Transfer from dense calibrated multi-camera positions to challenge detections can involve missing/offscreen objects, noisy ball localization, identity swaps, frame-rate and coordinate differences, and different possession definitions. These are anticipated domain-shift risks, not findings about the uninspected challenge. External performance supports a baseline and transfer hypothesis; it cannot establish challenge accuracy.

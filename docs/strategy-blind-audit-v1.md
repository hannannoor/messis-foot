## Initial recommendation

**Frozen independent recommendation, version 1.** I received only the neutral problem brief and consulted public primary sources. I did not inspect project files, code, chats, predictions, footage or labels. This message is the initial written record. Any later informed review should be appended separately.

**First test whether player movement can recover possession during ball gaps.** I would start with a CPU-friendly, offline sequence model that scores live/dead and home/away using separate evidence, then decodes them jointly over time. Give it short windows of team movement, visible-player counts, intermittent ball-control evidence, and qualified automatic events. Compare it with a simpler two-sided baseline that uses only the nearest reliable observations before and after a gap. The decisive question is how often movement recovers a *real opposing spell inside a gap whose two endpoints belong to the same team*. Simply filling such a gap with the endpoint team can improve frame accuracy while erasing exactly the turnover the user cares about.

**What the data can establish.** Consider two home-team touches ten seconds apart. Outside the camera view, home could retain the ball throughout, away could intercept and lose it, or play could briefly stop. All three histories can yield identical recorded tracks. Future observations narrow the possibilities but cannot distinguish these histories in every case. Opposite-team endpoints can establish that possession changed under compatible definitions, while leaving the number and timing of changes unresolved. Player motion offers statistical evidence during some gaps. In a primary study using player positions alone, frame-level live/dead F1 reached 0.93 while stoppage F1 was 0.80 under an evaluation that excluded stoppages shorter than two seconds. That result supports testing movement and illustrates why frame accuracy alone is inadequate. [Scientific Reports study](https://www.nature.com/articles/s41598-022-19948-1)

**Define the target before choosing a model.** Write down when an intercepted pass changes ownership, how a deflection differs from controlled recovery, when a restart becomes live, and how to treat replays or frames outside either playing period. FIFA explicitly distinguishes live contests from dead play. H/A/D/X cannot simultaneously encode a known live contest and epistemic uncertainty unless a separate reason is retained. For a provider-style *spell* definition, apply a documented convention, for example retaining the last controlling team through a loose ball until another team gains control. For a *controlled possession* definition, preserve known contests as a separate internal state and, if the interface requires X, export a reason distinguishing contest from insufficient observation. Full H/A/D coverage has a different meaning under those two contracts. [FIFA possession-state specification](https://www.fifatrainingcentre.com/media/native/world-cup-2022/Enhanced%20Football%20Intelligence%20EN.pdf)

## Experiments, in priority order

1. **Qualify the reference and timeline.** The DFL/Sportec release provides seven CC BY 4.0 matches with separate `BallPossession` and `BallStatus` fields. Treat inactive as D under that provider’s definition and quarantine both fields, aliases and downstream possession-derived fields from model inputs. Audit missing codes and transition disagreements with independent external references where available. Report ambiguous boundary intervals and sensitivity to alternative conventions. Seven matches support a pilot. Seek a separately held-out capture source for transfer evidence. SkillCorner documents both detected and extrapolated players as well as a frame possession field. Distinguish measured tracks from inferred ones, and establish label provenance before treating agreement as validation. [DFL/Sportec dataset paper](https://www.nature.com/articles/s41597-025-04505-y) · [SkillCorner schema](https://skillcorner.github.io/opendata/)
2. **Establish baselines on full matches.** Compare last reliable team, a two-sided gap bridge, nearest credible control when ball-visible, and a separate movement-only live/dead classifier. Use native frame IDs and timestamps, period IDs, side changes, and camera-cut boundaries. Keep an output row per original frame. Validate joins with synthetic fixtures for dropped frames, variable frame intervals, period resets and deliberately shifted tags. Admit an event stream only with documented clock correspondence or an automatic alignment whose residuals meet a predeclared tolerance. An uncertain clock should weaken or disable that stream. Never align against possession labels or hand-fit a clock on the supplied game.
3. **Test each source of incremental evidence.** Add a small boosted-tree team-motion model feeding a duration-aware sequence decoder. Features might include team-relative changes of shape, speed, local convergence, detected-player counts, and time since the closest credible ball sighting on each side. Test genuinely deployed automatic tags as noisy cues, separately from tracking, including with tags absent, shifted or wrong. Learn durations and calibrate confidence on separate external matches. A stronger challenger is a compact permutation-invariant player encoder or structured player-to-player path model. The PathCRF authors explicitly restricted training and inference to known in-play segments. Giving any contender true live/dead intervals in this task would remove an important part of the problem. [PathCRF methods](https://arxiv.org/html/2602.12080v1)
4. **Challenge the mechanism before promotion.** Split by match before windowing. Hold out whole providers or competitions where possible. Test natural ball gaps as the primary condition, and separately stress contiguous ball loss, simultaneous player loss, team-ID swaps, false ball detections, and camera cuts on licensed external data. Random independent frame masking answers a different question. Stratify by gap duration, visible-player count, same/opposite endpoints, D transitions and short opposing spells. A result obtained only with complete player tracks, oracle event timing, or synthetic corruption cannot establish deployment performance.

## Decision rule and disproof

**Decision rule.** Predeclare a meaningful coverage gain and tolerable error *before* opening external holdouts. One illustrative gate is at least **10 percentage points** more H/A/D coverage than the selective baseline, **at least 90% accuracy on newly assigned frames**, and a **paired lower confidence bound above −2 percentage points** for the change in team-spell F1. These are proposed operating tolerances, not predicted scores. Define a spell match in advance, for example one-to-one, same label, temporal intersection-over-union ≥0.5. Also report short-spell recall, D precision/recall, false switches per live minute, boundary timing error, and risk versus coverage by gap length. Treat X as uncovered, count it against recall on the full timeline, and report unmatched reference intervals separately. Use matches as uncertainty units and show individual results when the sample is small. A forced full-coverage export can retain the best hypothesis, confidence and evidence flags at every frame; report its own spell accuracy.

**What would change my recommendation.** I would drop the motion model if its gain disappears when extrapolated players and provider-derived inputs are removed, if a two-sided baseline matches it on held-out natural gaps, or if it achieves coverage chiefly by absorbing short opposing spells. I would withhold the full-coverage claim if independent references disagree as much as the claimed improvement, if clock uncertainty exceeds the boundary tolerance, or if no representative external holdout can test long gaps. In those cases the defensible result is the externally validated coverage range, with X retained for unsupported spans. Under the stated restrictions, accuracy on the supplied game itself remains unmeasured.

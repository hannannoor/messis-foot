# Response to the neutral audit

7 November2026. [Stage1](neutral-audit/neutral-audit-stage1.md) was written from competition details alone. [Stage2](neutral-audit/neutral-audit-stage2.md) saw actions/results without author reasoning. Both are preserved unchanged with [input/order hashes](neutral-audit/provenance.md).

The criticism is substantially right. Some work was real and useful, but we ordered important checks badly and over-emphasized an output count. The loader repair, leakage controls, explicit reference semantics and empirical ablations remain useful. The 27-policy search could not emit a label; its unchanged frozen test cannot establish useful motion recovery. More software tests and provenance do not turn that into a successful possession model.

## Concrete next work

1. Audit the target input contract with allowed automatic/synthetic checks: team mapping, frame/time units, coordinate freshness, selected-route reachability and geometry-gate applicability. Keep the manual/fixed-interval historical paths out of the selected route.
2. Freeze a cheap comparator set: incumbent, explicit carry, endpoint rule and agreement candidate. Acquire a small sufficiently representative licensed H/A/D cohort with real gaps and boundaries if available. Do not recycle the currently opened cohorts as untouched tests. If fresh data cannot be obtained, report that limitation rather than imply generalization.
3. Use the loss distribution to choose one change: restart/dead-state evidence, false-split control, or correcting bad anchors/hidden turns. Measure matched/spurious/missed spells and per-class frame F1. A richer model is not the default next step.
4. Package one selected local inference route and preserve its latent uncertainty/provenance. A carry materializer can supply a deterministic output convention without pretending it observed possession. Validate the CSV and reproduce its hash from clean runs before final entry.

No provided GT/video check, manual game labels, third-party code/weights import, new local inference or model retuning was performed in response to this audit. The audit does not independently certify our implementation or empirical accuracy; the reported checks/results are separately identified.

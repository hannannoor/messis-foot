# Public possession and temporal-inference implementations

Research date: 6 November 2026. Read-only research through the GitHub connector and primary papers. The only local project context read was `temporal-work/TEMPORAL_RECOVERY.md`. No raw/reference caches, per-frame outputs, challenge assets, videos or ground truth were inspected. No public code was executed, repositories cloned, or binary weights/datasets downloaded. No authors were contacted.

## Decision

The worthwhile missing idea is **player-indexed temporal possession inference**, rather than another team-level gap-filling rule. PathCRF demonstrates a concrete representation: a player holding the ball is a self-loop; a ball travelling between players is a directed edge. Such a sequence can represent H→A→H inside equal-team endpoints. This is representational capacity, not evidence that it reliably recovers hidden opposing spells in this project.

The first contained task remains the existing confidence-feasibility guard. After that, investigate a small player-indexed temporal encoder on independent external development data, with explicit visibility masks and abstention. Do not immediately adopt the full edge CRF, regress an entire ball trajectory, or install a large uncertainty library into the portable runtime. None of the inspected repositories supplies evidence sufficient to promote a local recovery policy.

## 1. PathCRF — strongest structural lead, substantial transfer limits

Pinned revision: `1b7c6f85a6b78c92e4543fde72ca2b86a933f997` (8 June 2026).

**Inspected implementation.** [models/set_lstm.py](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/models/set_lstm.py) is the relevant architecture entry point. [models/dynamic_sparse_crf.py](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/models/dynamic_sparse_crf.py) builds legal predecessor lists and performs log-space training and Viterbi decoding. It permits an opponent receiver and subsequent transitions from that receiver. Its outside self-loops are absorbing, so it assumes an episode boundary before a restart. This is richer than a two-team transition penalty, but still a hard choice of one path.

[dataset.py](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/dataset.py) uses team/GK indicators plus coordinates, velocity, speed and acceleration; ball features are optional and default off. Crucially, it skips episodes containing NaN node features. [inference.py, lines 401–407](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/inference.py#L401-L407) similarly returns no prediction when an input feature is NaN. Padding a roster is not equivalent to learning robust inference with temporally missing player observations. The current aggregate audit's many gaps with fewer than three available players per team make this a major limitation.

The inference wrapper needs episodes/phases. [datatools/utils.py](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/datatools/utils.py#L98-L124) constructs episodes using provider `ball_state == alive`. `evaluate=False` disables reference scoring but does not supply independent live/dead recognition. The optional `correct_episode_lasts` processes later predicted episodes to constrain earlier endings; it uses inferred next-episode events, not an automatic guarantee of correct boundary information. Leave it off for a contained baseline. The default `last_node=None` leaves the final state unconstrained.

**Paper-reported evidence, not rerun here.** The [KDD 2026 paper, v2](https://arxiv.org/html/2602.12080v2) uses seven DFL matches: five train, one validation, one test; known in-play episodes and 10-second windows at 5 Hz. Labels combine synchronized events with extra ball-direction-change touches. Dynamic masked CRF obtains 69.64% edge accuracy and 75.69% event F1; non-CRF constrained Viterbi obtains 73.14% event F1. Events require correct actor/type within one second. Seven-fold match validation yields 73.88±1.90% event F1. Sportec→proprietary K League transfer falls to 49.16±3.37%; the reverse yields 66.25±7.65%. Reported dynamic-model full-match latency is 22.88 seconds on an RTX 4090. No CPU benchmark, natural missing-ball selective precision, hidden-spell recall or independent stoppage result is reported.

**Reproduction and cost.** [saved/140/args.json](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/saved/140/args.json) records 3,431,031 parameters, 5 Hz, 10-second windows, `dynamic_sparse_crf`, and LOMOCV fold 6. The [pinned Git tree](https://api.github.com/repos/hyunsungkim-ds/pathcrf/git/trees/1b7c6f85a6b78c92e4543fde72ca2b86a933f997?recursive=1) confirms two checkpoint files for each of five variants; `saved/140/model/state_dict_best.pt` is 19,322,810 bytes. Binary contents/integrity and claimed scores were not verified. The committed script and stored checkpoint configuration differ in LOMOCV flags, so do not assume rerunning the example script reproduces that checkpoint.

[requirements.txt](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/requirements.txt) lists unpinned scientific Python packages but omits Torch, torch-geometric and kloppy despite source imports/README use. Parquet support also needs an engine. Training selects CPU when no GPU/MPS is available; inference defaults to CUDA and must explicitly receive CPU. The code is much larger than the current stdlib scorer. CPU latency and memory remain unmeasured; GPU timings cannot establish portable-runtime suitability.

**Terms.** [Root licence](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/LICENSE): MPL-2.0. No separate checkpoint licence/model card was found in the pinned tree; do not assert a separate model-weight grant or redistribute checkpoints without resolving applicability. DFL data remain separately CC BY 4.0, as documented in the project's aggregate context and the [dataset publication](https://doi.org/10.1038/s41597-025-04505-y). Synchronized event files in this repository do not make data terms disappear.

**Recommendation.** Use the state representation and matched ablations as references. First establish whether a player-indexed temporal classifier adds signal over the existing aggregate-tree emissions. Compare unconstrained predictions with a simple constrained decoder before adding dynamic transition networks. Full PathCRF training additionally needs player/edge touch supervision; the existing team-possession phases alone cannot reproduce that target. The seven DFL matches are already seen here and cannot become a fresh independent final test.

## 2. MAPIE — explicit selective risk, not extra possession evidence

Pinned revision: `c073876f271d28a05e4c2b53639293ff3a805203` (2 November 2026).

**Inspected implementation.** [mapie/risk_control/multi_classification.py](https://github.com/scikit-learn-contrib/MAPIE/blob/c073876f271d28a05e4c2b53639293ff3a805203/mapie/risk_control/multi_classification.py) implements `MultiClassificationLTTController`: threshold a fitted classifier, return `np.nan` below threshold, and control class-specific risks over a finite threshold set. [risks.py](https://github.com/scikit-learn-contrib/MAPIE/blob/c073876f271d28a05e4c2b53639293ff3a805203/mapie/risk_control/risks.py#L381) supplies `build_precision_ovr`; [fwer_control.py](https://github.com/scikit-learn-contrib/MAPIE/blob/c073876f271d28a05e4c2b53639293ff3a805203/mapie/risk_control/fwer_control.py) supplies multiplicity procedures. The API explicitly allows no valid threshold. The [binary controller](https://github.com/scikit-learn-contrib/MAPIE/blob/c073876f271d28a05e4c2b53639293ff3a805203/mapie/risk_control/binary_classification.py) also supports a finite set of multi-parameter decision policies. These are inspected interfaces, not tests run here.

The primary [Learn then Test paper](https://arxiv.org/html/2110.01052v5) frames policy selection as multiple hypothesis tests and assumes an IID calibration sample; it includes selective classification. The [MAPIE paper](https://proceedings.mlr.press/v204/cordier23a.html) concerns uncertainty-method implementation, not football possession. Neither establishes accuracy for this project.

**Useful adaptation.** After fixing feasibility, calculate risk/coverage and accepted-label precision separately for new H and A labels. Freeze the scorer before calibration and allow the result “no policy qualifies.” Use independent matches or explicitly defined interval/block losses as support units; native/resampled frames within a match are correlated. Simply feeding 25 Hz frames into MAPIE does not yield a valid certificate. Match-level bounded loss can support a different risk estimand, but a few independent matches may be too few for a useful guarantee. It also cannot certify hidden-spell recall when there are no qualifying natural hidden spells.

**Terms and cost.** [Licence](https://github.com/scikit-learn-contrib/MAPIE/blob/c073876f271d28a05e4c2b53639293ff3a805203/LICENSE): BSD-3-Clause. No pretrained possession weights/data are involved. [pyproject.toml](https://github.com/scikit-learn-contrib/MAPIE/blob/c073876f271d28a05e4c2b53639293ff3a805203/pyproject.toml) requires Python≥3.10, NumPy≥1.24.1, sklearn≥1.4 and SciPy≥1.10. Keep it in offline development if used. A fixed scalar threshold adds negligible deployment computation; a small audited equivalent can remain stdlib-only. Full calibration cost depends on the policy grid and data; no measured CPU timing was obtained.

**Rejection boundary.** Risk control selects when to trust a signal. It does not repair weak emissions, guarantee transfer across providers, or make an unattainable confidence gate useful. Ordinary marginal conformal label coverage is not the same target as precision among newly emitted H/A labels.

## 3. Ball Radar — useful hierarchical comparison, not ready to vendor

Pinned revision: `2486896cfb933ecd304489883241a00e3645ca8c` (6 July 2023).

**Inspected implementation.** [models/player_ball.py](https://github.com/hyunsungkim-ds/ballradar/blob/2486896cfb933ecd304489883241a00e3645ca8c/models/player_ball.py) combines team-specific/equivariant and global Set Transformer representations, a player-possession classifier and ball regressor. [scripts/player_ball.sh](https://github.com/hyunsungkim-ds/ballradar/blob/2486896cfb933ecd304489883241a00e3645ca8c/scripts/player_ball.sh) specifies bidirectionality, 11 players/team, six features and partial-ball masking. [postprocessor.py](https://github.com/hyunsungkim-ds/ballradar/blob/2486896cfb933ecd304489883241a00e3645ca8c/postprocessor.py) is the separate rule-based physical/touch reconstruction stage. This makes the direct possession head a useful architecture reference without requiring the ball-regression stage.

**Paper-reported evidence, not rerun here.** The [KDD 2023 paper](https://arxiv.org/html/2306.08206v1) trains on ten proprietary Fitogether matches plus Metrica games 1–2, validates on two Fitogether matches plus game 3 first half, and tests on three Fitogether matches plus game 3 second half. Validation/test therefore share a Metrica match. It uses known in-play episodes and 10-second, 10 Hz windows; GPS reference ball trajectories are reconstructed from annotated events and inferred goalkeeper positions. The main H-LSTM-RL reports 3.6561 m position error, 64.70% player and 85.85% team possession accuracy. Its separate randomly masked-ball experiment reaches 97.41% team accuracy with 20% ball observations before postprocessing, versus 83.96% at zero observations. Random masks do not establish performance on long natural gaps, and these frame metrics do not establish team-spell recovery.

**Terms/reproduction.** The [pinned tree](https://api.github.com/repos/hyunsungkim-ds/ballradar/git/trees/2486896cfb933ecd304489883241a00e3645ca8c?recursive=1) has no project-wide licence and no `.pt`/`.pth` checkpoints; only `set_transformer/LICENSE` is present. That component licence does not license the whole project. [README](https://github.com/hyunsungkim-ds/ballradar/blob/2486896cfb933ecd304489883241a00e3645ca8c/README.md) says proprietary Fitogether data cannot be shared and points to preprocessed Metrica data on Drive. The [Metrica provider README](https://github.com/metrica-sports/sample-data/blob/master/README.md#legal-stuff) asks responsible use and acknowledgement for public use; it is not a clear standard open-data redistribution licence. No model-weight terms were found because no model weights are released in the inspected tree.

README specifies Python 3.10/Torch 1.13.0; [requirements.txt](https://github.com/hyunsungkim-ds/ballradar/blob/2486896cfb933ecd304489883241a00e3645ca8c/requirements.txt) omits Torch and version pins. CPU inference was not measured. Bidirectional processing needs future context; full model and postprocessing add much more cost and tuning surface than the existing tree/HMM.

**Recommendation.** Learn from hierarchical player possession and partial-ball conditioning. Do not copy unlicensed project code or add ball regression merely to turn inferred coordinates back into possession. The latter compounds imputation and nearest-player errors, and published postprocessing can lower possession accuracy.

## 4. MIDAS — relevant to missing players, defer for this task

Pinned revision: `a92ebc2fd35d9f3f08ad4c72a552007d377bb88a` (20 June 2025).

**Inspected implementation.** [models/midas/midas.py](https://github.com/gkswns95/MIDAS/blob/a92ebc2fd35d9f3f08ad4c72a552007d377bb88a/models/midas/midas.py) wraps player-mask generation and the imputer; [midas_imputer.py](https://github.com/gkswns95/MIDAS/blob/a92ebc2fd35d9f3f08ad4c72a552007d377bb88a/models/midas/midas_imputer.py) and [scripts/midas_soccer.sh](https://github.com/gkswns95/MIDAS/blob/a92ebc2fd35d9f3f08ad4c72a552007d377bb88a/scripts/midas_soccer.sh) provide derivative accumulation, bidirectional inference and hybrid prediction. Its target is players, not team possession. The camera-mask simulator uses ball data to create the observation mask; a real-input adapter would need to accept observed masks rather than simulate them from an unavailable true ball.

**Paper-reported evidence, not rerun here.** [MIDAS v4](https://arxiv.org/html/2408.10878v4) studies player imputation using three Metrica matches, 20-second windows at 10 Hz, dynamic training missing rates and 50% test missingness. First/last five frames are always observed. Soccer camera-mask position error is 1.2296 m versus cubic spline 1.9209 m and linear interpolation 3.1083 m. The paper reports 3,945,579 parameters and 24.32 ms per window on TITAN RTX; CPU cost is unmeasured. It reports no missing-ball team-spell or hidden-turnover result. The inspected training code uses games 1–2 for training and `match3_valid.csv` for validation; the repository does not make its full split/data preparation reproducible from a fresh checkout alone.

**Terms/reproduction.** The [pinned tree](https://api.github.com/repos/gkswns95/MIDAS/git/trees/a92ebc2fd35d9f3f08ad4c72a552007d377bb88a?recursive=1) contains neither a project licence, trained checkpoints nor the `requirements.txt` named in README. Only the vendored Set Transformer has a licence. README specifies Python 3.8.18/Torch 1.10.1; `models/utils.py` also imports Shapely and scientific packages. Metrica terms remain separate; basketball/NFL data require their own terms and are unnecessary here.

**Recommendation.** Defer unless insufficient player visibility is first shown to be the limiting factor on independent data. If revisited, keep imputed player coordinates explicitly marked, compare against observed-only inference, and require possession/spell improvement as well as coordinate error. Do not transform synthetic player tracks into supposedly observed possession evidence.

## Other leads screened out

- **TranSPORTmer:** the [primary ACCV paper](https://arxiv.org/html/2410.17785v1) is directly relevant to masked ball inference and four game states. Its soccer study uses 283 proprietary LaLiga matches with disjoint-match splits. No official public repository/checkpoints were located through the paper and repository searches. PathCRF includes [models/transportmer.py](https://github.com/hyunsungkim-ds/pathcrf/blob/1b7c6f85a6b78c92e4543fde72ca2b86a933f997/models/transportmer.py), but that is another team's implementation, not an official reproduction of the original ball/state system. Do not imply deployable pretrained live/dead inference is available.
- **Graph Imputer:** the [primary football paper](https://www.nature.com/articles/s41598-022-12547-0) concerns stochastic off-screen player reconstruction, not possession recovery. MIDAS contains a baseline implementation. This adds missing-player reconstruction and sampling cost before proving it improves the task target; it is lower priority than using available real player motion.
- **Common YOLO/ByteTrack possession demos:** nearest-ball player rules, linear interpolation and carrying the last owner do not add the missing mechanism identified here. The existing endpoint-rule experiment already demonstrates why fewer X labels alone are inadequate.

## Contained next experiment and stopping rules

1. **Fix the experiment contract first.** Add the analytic attainable-score bound and a synthetic undecided-row reachability check for every calibration/decoder/gate combination. Report an empty eligible set directly. Preserve the frozen rejected experiment and its final results.
2. **Audit representable input before training.** From independent external aggregate summaries, measure player identity continuity, observed-player counts, full/partial visibility and native gap-length support. PathCRF-style complete-roster assumptions cannot be silently filled by extrapolation. If sufficient observed motion is absent, stop; these repositories cannot manufacture evidence.
3. **Test the smallest distinct hypothesis.** A player-indexed short temporal encoder with explicit missingness, supervised by existing external team phases, is a smaller experiment than full player-edge CRF plus ball regression. Compare against existing frame/tree emissions with the same decoder, calibration, eligible gaps and coverage budget. This is a proposed adaptation, not a ready-made repository capability or a validated superiority claim.
4. **Separate evidence targets.** Score newly emitted H/A agreement, match-level team-spell change and hidden opposing-spell recovery with X counted as a miss. Stratify short/long gaps and equal/different endpoints. Require natural hidden-spell support; synthetic masks can test a mechanism but cannot replace absent natural evidence. Current zero natural qualifying hidden spells remains a limiting fact.
5. **Freeze before final scoring.** Use disjoint external development/calibration/validation/final groups, preserve provider provenance and native support units, and do not recycle the eight already opened final matches as a new untouched test. No challenge tuning, video review, manually supplied game cues or local inference is warranted by this research.

The recommendation is therefore one small feasibility/risk audit followed, only if support permits, by one player-indexed temporal experiment. Full graph sequence models, diffusion, general trajectory reconstruction and a larger decoder are deferred until a simpler matched comparison earns them.

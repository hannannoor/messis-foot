# Public GitHub scout: recovering observations before assigning possession

Research date: 6 November 2026. Scope: public source code, documentation, licences and published aggregate evaluations. GitHub connector reads were preferred; primary papers supplied evaluation context. Nothing was installed or executed, and no dataset, model checkpoint, video, challenge asset, ground-truth file, saved tracker state or per-frame prediction asset was downloaded or inspected. Directory inventories were read to locate source files; asset names in those inventories were not followed. No authors were contacted. This note is the only workspace file written by this scout.

The starting evidence is the aggregate [temporal experiment report](../../TEMPORAL_RECOVERY.md) and the task owner's source summary: players already survive missing-ball rows, coordinates already pass a homography gate, the motion H/A challenger was rejected, many ball gaps are long, and the two cameras do not yet have a qualified bounded time mapping. These observations were not independently re-audited here. A new detector can add image evidence; a tracker can associate evidence; interpolation can only estimate between evidence. None establishes team control, live/dead state, or a hidden turnover by itself.

### 1. WASB-SBDT: recover ball candidates from pixels

The [model configuration](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/src/configs/model/wasb.yaml) uses three frames in/three heatmaps out at 512 × 288, with HRNet stem strides removed. [HRNet implementation](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/src/models/hrnet.py#L258) and [detector adapter](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/src/detectors/detector.py#L19) are concrete entry points. The [evaluation runner](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/src/runners/eval.py#L24) accumulates candidates from overlapping windows before selection. An adapter should emit those candidates with source frame/time and confidence, rather than only a rendered trajectory.

Author-reported soccer results are F1 88.3%, AP 83.6%, 55.7 FPS for step 3; step 1 gives F1 88.2%, AP 86.2%, 23.6 FPS. Evaluation uses a four-pixel tolerance; these are detector benchmarks, not possession accuracy. The soccer split is four training views and two test views of one match, so it offers little match independence. The authors reannotated the ball because original ISSIA annotations were mislocalized. Their experiments used a four-V100 server. This prevents a fair direct comparison with older FootAndBall numbers from different annotations. The paper's soccer ablation found no gain from online tracking. See the [primary paper, Tables 1–4 and Sections 3–5](https://arxiv.org/html/2311.05237v2).

Important implementation discrepancy: [online.py](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/src/trackers/online.py#L30) defines an acceleration predictor, but `_select_best` sets `xy_pred = None`; `update` never calls `Track.predict`. Its displacement gate compares a candidate with the previous observed position, not the paper's predicted position. No candidate means invisible output; this is not an occlusion inpainting engine. Treat the code as the inspected implementation, not as proof of the paper's motion equation being active.

Rights/runtime: [MIT code licence](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/LICENSE.md); the HRNet file retains Microsoft's MIT header. [Model Zoo](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/MODEL_ZOO.md) supplies external checkpoint links but does not expressly state separate weight terms. Do not infer that every checkpoint or underlying dataset is MIT. [Dockerfile](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/Dockerfile) pins Torch 1.11/CUDA 11.3 and older scientific packages; [detector initialization](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/src/detectors/detector.py#L41) explicitly rejects CPU. Weight use remains unapproved/unresolved in this scout.

Adaptation judgment: short temporal context and alternate candidate retention may recover small, blurred or partly hidden balls that a single-frame front end drops. A long fully invisible interval remains unsupported. The two cameras need separate image preprocessing and quality summaries. A fixed 300-pixel [displacement threshold](https://github.com/nttcom/WASB-SBDT/blob/923462cacdeb3353b84ddebdedb3f4b7a8553b0f/src/configs/tracker/online.yaml) is not portable across camera motion, frame rate, resizing or cuts. Calibrate any replacement gate only on independent authorized development footage. Field calibration is unnecessary for pixel detection; it becomes necessary when converting recovered pixels to control distances.

### 2. PnLCalib: improve the evidence admitted by the geometry gate

[inference.py](https://github.com/mguti97/PnLCalib/blob/42088864170f75ea02e76d20e9a9a1db59edb3e3/inference.py#L64) predicts keypoint and line heatmaps, completes geometric intersections, and calls `FramebyFrameCalib.heuristic_voting`. The [calibration implementation](https://github.com/mguti97/PnLCalib/blob/42088864170f75ea02e76d20e9a9a1db59edb3e3/utils/utils_calib.py#L364) builds correspondences, uses geometric/RANSAC alternatives, and supports nonlinear point-and-line refinement. [Ground-plane homography](https://github.com/mguti97/PnLCalib/blob/42088864170f75ea02e76d20e9a9a1db59edb3e3/utils/utils_calib.py#L646) and [heuristic selection](https://github.com/mguti97/PnLCalib/blob/42088864170f75ea02e76d20e9a9a1db59edb3e3/utils/utils_calib.py#L683) are separate useful adapters. The demo supports `--device cpu`; the [requirements](https://github.com/mguti97/PnLCalib/blob/42088864170f75ea02e76d20e9a9a1db59edb3e3/requirements.txt) nevertheless include a Linux CUDA/Triton environment, so Windows/CPU installation is not a drop-in promise.

The [authors' CVIU manuscript, Table 3](https://www.iri.upc.edu/people/aagudo/Papers/JCR/CVIU/CVIU2026/mgutierrezperez_aagudo_cviu26.pdf) reports mean whole-field IoU improving from 92.4% to 93.4% on WC14-test and from 94.6% to 96.3% on TSWC-test with PnL refinement, using the paper's dataset-specific training/fine-tuning protocols. These are field-registration metrics. They do not demonstrate ball detection, temporal continuity, two-camera synchronization or possession. The manuscript also documents cases where isolated point/line refinements worsen some metrics. The repository provides reproduction scripts, which this scout did not run. Do not confuse the earlier arXiv v2 “No Bells, Just Whistles” paper with the current PnL extension.

Rights: the pinned [README licence section](https://github.com/mguti97/PnLCalib/blob/42088864170f75ea02e76d20e9a9a1db59edb3e3/README.md#license) explicitly separates GPL-2.0-or-later code, CC BY 4.0 released `SV_*`/`MV_*` weights, MIT HRNet-derived files and third-party `sn_calibration/` evaluation code. The 26 October 2026 commit clarifies weight terms; the authors state that their former SoccerNet research agreement adds no further checkpoint restrictions. Preserve that provenance and attribution if later acquired; the weight statement does not license training videos or annotations. No checkpoint was fetched here.

Adaptation judgment: evaluate whether this can recover valid coordinates on rows the current homography gate rejects, with false acceptance and field-coordinate error reported together. This is incremental to the existing gate. Two cameras may have different distortion, field visibility and mirrored orientation. Automatic keypoints avoid challenge-specific clicks, but sparse/occluded markings, wrong semantic line identity and pitch dimension assumptions can still yield plausible wrong transforms. Use actual field dimensions when independently known; otherwise carry the model assumption explicitly. The demo is frame-by-frame, with no demonstrated bounded camera-state interpolation or probabilistic calibration uncertainty. Do not reuse the last valid transform through a cut or indefinitely through a pan/zoom.

### 3. FootAndBall: economical detector comparator

[network/footandball.py](https://github.com/jac99/FootAndBall/blob/01261092a93de55026745e532a2e12188ad86801/network/footandball.py#L136) has a ball confidence map at quarter input resolution and a separate player box head; [candidate extraction](https://github.com/jac99/FootAndBall/blob/01261092a93de55026745e532a2e12188ad86801/network/footandball.py#L148) applies local maxima and scores. [run_detector.py](https://github.com/jac99/FootAndBall/blob/01261092a93de55026745e532a2e12188ad86801/run_detector.py#L47) loads onto CPU/CUDA and runs whole frames. It is a relatively small inference adapter, with no field calibration needed at detection time.

The [primary VISAPP paper, Section 4/Table 2](https://arxiv.org/html/1912.05445v2) reports 0.909 ball AP and 0.921 player AP on ISSIA-CNR, 199k parameters and 37 FPS for 1920 × 1080 on a GTX 1060. Its Soccer Player dataset player AP is 0.885, below the comparison Faster R-CNN's 0.928. This is useful measured evidence for full-resolution small-object detection, with limited domain breadth; original ISSIA annotation concerns identified by WASB limit cross-paper comparison. No two-camera fusion, ball identity persistence, long occlusion recovery, uncertainty calibration or team possession is supplied.

Rights/runtime: [MIT source licence](https://github.com/jac99/FootAndBall/blob/01261092a93de55026745e532a2e12188ad86801/LICENSE); [README](https://github.com/jac99/FootAndBall/blob/01261092a93de55026745e532a2e12188ad86801/README.md) names a bundled checkpoint trained with ISSIA cameras 1–4 plus SoccerPlayerDetection set 1, and tests Python 3.8/Torch 1.10.2/Ubuntu. The README expressly licenses code, without a separate explicit checkpoint/data grant. Treat checkpoint rights as unresolved before execution or redistribution. CPU execution is present in source; CPU speed on our hardware is unmeasured.

Adaptation judgment: use as a low-complexity comparison with the existing detector and WASB. Preserve competing ball maxima; shoes, heads and advertising remain false-positive risks. Its default 0.7 confidence is not a calibrated error probability. Long missing intervals, two camera clocks and image-to-pitch mapping remain separate problems. No manual field setup is required for pixel inference.

### 4. sn-gamestate / TrackLab: player continuity and reproducible module boundaries

The pinned [pipeline configuration](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/sn_gamestate/configs/soccernet.yaml) selects YOLO, PRTReID, BPBreID/StrongSORT, calibration and tracklet aggregation. [prtreid_api.py](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/sn_gamestate/reid/prtreid_api.py#L41) exposes embeddings, body visibility and role confidence. [bbox2pitch.py](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/sn_gamestate/calibration/bbox2pitch.py#L63) projects bottom box points onto Z=0 and handles missing calibration. These interfaces suggest keeping detection, identity, role and coordinates independently nullable. Current source already retains players without the ball; that behavior is not a new contribution from this repository.

The [GSR primary paper, Table 1](https://arxiv.org/html/2404.11335v1) reports test GS-HOTA 22.26 for the original full baseline, versus 57.64 when evaluated only as image-space tracking without pitch/identity attributes. This exposes the gap between good image tracks and usable identified pitch positions. GS-HOTA is an athlete localization/identity metric, not ball-control or possession validation. The published original baseline result is not a fresh evaluation of the 2026 configuration. The [README](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/README.md) records the May 2026 TrackLab update fixing broken GS-HOTA evaluation and past coordinate/team annotation fixes; dataset/evaluator versions must be pinned in any replication.

The [GPLv3 licence file](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/LICENSE) is not a blanket licence for its external dependencies or downloaded models. [pyproject.toml](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/pyproject.toml) requires Python 3.9, Torch 1.13.1, TrackLab 1.3.24, MMOCR/MMDetection and Git dependencies for PRTReID/BPBreID. The documented baseline auto-downloads datasets and checkpoints on first run: do not run its quickstart as a source-only probe. An adoption review must separately resolve the current YOLO, ReID, OCR, calibration and model terms.

Adaptation judgment: player ReID may reduce fragmented identities after short occlusions, but cannot observe a fully hidden ball or prove control. Full-stack installation is disproportionate until a source-only audit identifies a specific missing player association capability. Keep association scores and identity resets; do not make a Kalman prediction look like a detector observation. The [team-side module](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/sn_gamestate/team/tracklet_team_side_labeling_api.py#L24) uses mean field x positions and goalkeeper side. That camera-relative heuristic is not a valid universal home/away mapping for mirrored views, halves, or attacking clusters. Cross-camera identity association needs a separate validated time map and shared coordinate convention.

### 5. BroadTrack: strong temporal calibration evidence, unsuitable reuse licence

The [published method](https://arxiv.org/html/2412.01721v1) combines field marking segmentation, optical flow, a broadcast-camera/tripod model, confidence and reinitialization. It reports JaC5 56.88, mean reprojection error 5.02 pixels and 100% completeness on 49 thirty-second HD test clips from three Swiss league games; the TVCalib comparator is 19.88, 12.4 pixels and 99.93%. Reported reinitializations numbered 33, with mean loss duration 15 frames. The extra twenty-minute demonstration is qualitative, not an independent dense long-run evaluation. These are geometry results, not possession or synchronization results.

The inspected implementation entry points are [CameraTracker.cpp](https://github.com/evs-broadcast/BroadTrack/blob/31d4703c9a9ff84eeda36c8667c433a72cdace1f/CameraTracker.cpp), [main.cpp](https://github.com/evs-broadcast/BroadTrack/blob/31d4703c9a9ff84eeda36c8667c433a72cdace1f/main.cpp#L440), [CMakeLists.txt](https://github.com/evs-broadcast/BroadTrack/blob/31d4703c9a9ff84eeda36c8667c433a72cdace1f/CMakeLists.txt) and [Dockerfile](https://github.com/evs-broadcast/BroadTrack/blob/31d4703c9a9ff84eeda36c8667c433a72cdace1f/Dockerfile). The code uses confidence thresholds 0.3/0.2 in its loss/reinitialization handling and 0.5 elsewhere; these should not be conflated with the paper's reported 0.5 reinitialization protocol. It requires LibTorch, Ceres, OpenCV, Boost and detector models. CPU fallback appears in detector wrappers, but the packaged build targets CUDA 12.4 and CPU performance is unmeasured.

Its [EVS licence](https://github.com/evs-broadcast/BroadTrack/blob/31d4703c9a9ff84eeda36c8667c433a72cdace1f/LICENSE) limits use to noncommercial internal research, restricts redistribution, contains confidentiality provisions and assigns modifications/derivatives to the licensor. This is not permissive open-source reuse. No code, models or derivatives were copied into the workspace. Use the published research as a design reference; do not integrate this implementation or its bundled detector weights under an assumption of MIT/GPL terms.

Adaptation judgment: the missing idea is temporal *camera* confidence with reset/reinitialization, rather than accepting an old homography forever. The [README workflow](https://github.com/evs-broadcast/BroadTrack/blob/31d4703c9a9ff84eeda36c8667c433a72cdace1f/README.md) estimates tripod parameters from an initial calibration run, so it carries camera-specific state and assumptions. It suits elevated tripod/pan/tilt/zoom views, with separate camera states. It does not justify a common tripod for two cameras, a handheld/fisheye camera model, or manual match-specific fitting. Licence constraints and geometric assumptions make this a later research reference, not the next integration task.

## Proposed adaptation order and external acceptance evidence

These are recommendations for a separately authorized development phase, not changes made here. They do not revive or retune the frozen H/A experiment.

1. **Specify the observation contract and independent test corpus first.** Retain camera ID, native frame index/PTS, time-map version, pixel candidate set, detector confidence, visibility, calibration ID/quality and measured-versus-estimated provenance. Preserve unknown values independently for ball, player identity, coordinates and control. Use synthetic probes and separately licensed external matches; split by match/camera rather than random adjacent frames. Public data being downloadable does not alone settle its use terms. Do not evaluate or select on this challenge's footage, labels, calibration landmarks or output locations.
2. **Compare pixel recovery before tactical labels.** Compare current detector, WASB and optionally FootAndBall under a fixed external budget. Report visible-ball recall, false detections per minute, localization error, recovered interval count/length, confidence calibration and runtime per camera regime. Break down small/blurred/occluded/offscreen balls and cuts. Overlapping windows are extra computations on the same frames, not independent evidence. A lower missing fraction is not sufficient acceptance.
3. **Measure geometry recovery separately.** Compare PnLCalib and the present homography gate on independent sequences. Report accepted coverage together with false acceptance, world-position error and temporal jumps, including bad keypoints/lines and camera cuts. A small residual fitted to the same incorrect line identities is not an uncertainty guarantee. Establish coordinate axes, metric scale and half/camera orientation explicitly. Player feet may use Z=0; an airborne ball cannot be located on the pitch by simply applying the same plane homography to its image center.
4. **Gate any second-view evidence on a qualified clock model.** Proposed requirements are native timestamps, camera/shot/half identity, monotonic bounded mapping, bounded drift, several independent visual correspondences and explicit discontinuity/replay handling. Score ambiguity and retain alternative offsets; reject if a unique narrow correspondence cannot be established. OCR game clocks alone can repeat, stop, be absent or remain onscreen during replays. Audio can be delayed or shared independently of picture. Neither signal alone qualifies frame alignment. BroadTrack, PnLCalib and replay grounding do not supply this clock model. Validate synchronization on independent paired recordings with known offsets, rate mismatch, dropped frames, replays and non-overlap before any local fusion.
5. **Keep interpolation an explicitly estimated layer.** No source reviewed justifies bridging the existing long ball gaps. If short bounded bridges are later tested, learn caps/error bounds externally, require valid endpoints in the same continuous camera/coordinate/time regime, stress abrupt kicks/turnovers/cuts, and compare against leaving the gap unknown. Preserve native support units and uncertainty growth; never convert the bridge into an independent observed control anchor. Two same-team endpoints can conceal an opposing spell. Two-view triangulation additionally requires simultaneous visibility, reliable ball correspondence and full calibrated camera geometry; two arbitrary homographies do not provide it.
6. **Only then test downstream benefit under frozen gates.** New H/A/control labels must be supported by newly admitted observations and separately evaluated for precision, team-spell quality and hidden-turnover preservation. Keep the prior baseline/output unchanged until those external criteria pass. Player smoothing, a better-looking radar, a stable track ID or a smaller X count cannot substitute for this evidence.

The most contained next technical proposal is a detector-candidate benchmark adapter, with explicit weight/data rights resolution and synthetic timestamp/provenance probes. PnLCalib is the second focused experiment if aggregate source audits show coordinate rejection is a material bottleneck. A broad tracker rewrite or long-gap possession filling is not warranted by the evidence found here.

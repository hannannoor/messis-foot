# WCSF container amendment: revision 2

9 November 2026. Small input-packaging change, planned before implementation. The first pinned archive exactly matches its byte count and Git blob but contains one CSV plus a 163-byte `__MACOSX/._positions_FIRST_HALF.csv` AppleDouble sidecar. The v1 sole-CSV rule rejected it before opening the CSV, creating stores, downloading half 2 or invoking a model. See `reports/wcsf-transfer/failure.json`. All 174 v1 source files are preserved locally and in prospective Git commit `61a90e331d1e025a00ab3e84e5b5827be654d9a8`.

Two routes were considered: stop this useful source at a non-data packaging artifact and return to C, or explicitly amend the container contract before any CSV ingestion. The planner chooses the latter under the user's authorization to plan/execute next work. This supersedes the original plan's stop-and-return rule **only for this observed container mismatch**. It is not an automatic retry or a geometry/label/model adjustment. Any unresolved geometry or actual data-contract failure still stops scoring and returns to C.

Revision 2 permits exactly one real CSV and at most one additional small sidecar. All member paths, duplicate names, symlink/encryption, size and compression-ratio checks still apply. The optional sidecar must have exactly the path `__MACOSX/._<real CSV basename>`, size 4..4096 bytes and the four-byte AppleDouble magic `00 05 16 07`. Its contents are ignored after that bounded header check; it is not another input CSV. Reject an extra genuine CSV, wrong metadata name/magic, oversized sidecar or any unrelated file. The magic is specified by [RFC 1740](https://www.rfc-editor.org/rfc/rfc1740.html); this is a narrow packaging exception for the hash-pinned source, not a general-purpose AppleDouble decoder.

Implement a fixture test that the valid sidecar succeeds and each impostor fails; watch it fail under v1, implement the small change, run the focused source tests and full suite. Add this amendment to the prospective source inventory. Use new public `reports/wcsf-transfer-v2` and private `wcsf-reference/wcsf-2026-11-09-2` generations. Preserve v1 source/freeze/failure and archive; never overwrite its receipt to imply success. Publish v2 code and freeze before a new acquisition/ingestion attempt. Redownloading the same pinned first half is allowed and disclosed: at most three archive transfers across both generations, two distinct source assets.

All four reconstruction hypotheses, numerical bounds, parser/reference/time contracts, model/scorer, method IDs and window/cost settings remain unchanged. The first v1 acquisition exposed only ZIP metadata, not reference values or model outcomes. Machine reference access will be logged at v2 ingestion as originally designed. No outcome-guided choice or new score comparison is introduced. The final independent code/evidence review remains after the retained scientific failure-or-result package.

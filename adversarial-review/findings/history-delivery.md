## 3. What a user can actually run

### Existing one-file frozen tactical route

`README.md:23–34` promises `football_pipeline.py tactical run ...`, not the latest neutral policy. The file's version is `2026.11.06-temporal-research` (`football_pipeline.py:22`). Eight newer checkout modules are absent: `accuracy_protocol`, `anonymous_motion`, `candidate_cli`, `confidence_ensemble`, `input_contract`, `materialization_control`, `soft_sequence`, and `temporal_feasibility`. The top-level new candidate drivers are absent too. That is deliberate preservation, consistent with README:50, rather than corrupted bundling.

The old tactical route embeds its model and does not need the external benchmark directory for default inference (`tactical_cli.py:75–85`). It excludes Smart Tagging from selected features, rejects injected dead evidence in geometry CSV input (`:88–95`), and reports no video/GT/fitting/fixed-D use (`:122–150`). Its .8 support, stable-run and bounded owner-continuity policy is different from the newest neutral/cost-32 route. Therefore a user following the prominent command gets a coherent documented older model, but not the newest headline method.

`build_standalone.py:9–11` would bundle *all current* `gap_solver` modules if run today, while `:65–78` still hardcodes the temporal-research version and dispatches only legacy/camera/tactical commands. It does not export the new top-level neutral candidate. Blindly rebuilding the bundle is consequently not a solution to the latest delivery problem; preserve the frozen bundle and introduce a separately named export with a defined dependency manifest and policy identity.

The existing standalone's first-page docstring is also stale: `football_pipeline.py:13–14` says fixed-D context is included and there is no general live/dead classifier, while its tactical command has a separate model and excludes that context. The longer guide qualifies the history, but `--help`/header/version should describe routes explicitly. This is a small concrete wording fix, not evidence that the tactical code secretly uses the shortcut.

## 4. Reproduction has three different levels

1. **Reusing committed models for local/synthetic inference:** available from the checkout (latest) or standalone (older). No training environment or private reference arrays required. Source/model/evidence pinning must remain intact for the latest command.
2. **Rebuilding external inputs and evaluating the older frozen experiments:** concrete source recipes exist. `benchmark/README.md:9–32` prepares checksum-verified DFL inputs, baseline and archived frozen-model evaluation; about 2.63 GB is documented. `benchmark/skillcorner/README.md:3–45` pins the source revision, MIT licence, approximately 1.82 GB tracking, preparation and frozen rejected-artifact diagnostic evaluation. `requirements-training.txt:1–5` pins Python 3.12 and four libraries. These are meaningful reproducibility provisions, not empty hashes.
3. **Exactly replaying the newest published sealed comparison:** original generation-specific caches and score archives are still required. `docs/ball-gap-results.md:44–66` says so directly, and instructs a separate copy preserving old receipts. Calling that copy “clean” means clean *new output stage*, not raw-data-only fresh-clone reproduction.

The third limitation has a concrete mechanism. SkillCorner `save_motion_cache` generates `uuid.uuid4().hex` (`gap_solver/skillcorner.py:215–223`), embeds it in feature and reference arrays and metadata (`:245–253`), and verifies paired array hashes/generation on load (`:257–271`). A legitimate rebuild from identical licensed raw input therefore creates a different generation identity and byte hashes.

The older temporal evaluator intentionally distinguishes stable raw/adapter identity from a generation: `evaluate_temporal_final.py:25–30` validates `source_cache_identity`; the regression in `tests/test_temporal_review_regressions.py:70–79` explicitly permits a rebuilt generation with unchanged stable input identity and rejects changed raw input. This was already solved at that layer.

The newer accuracy experiment instead freezes full metadata/features/reference file hashes (`accuracy_experiment_frozen.py:89–114`) and enforces them before preparing/loading scores (`:127–145`). Ball-gap then freezes every original `.npz`/`.json` score archive plus the old input hash map (`ball_gap_experiment.py:130–148`). Thus new source acquisition is not enough to regenerate the *same existing sealed lineage*. One cannot just document “rerun preparation” and make the existing UUID-bound seals pass. This is a real portability regression across experiment generations.

Concrete change: preserve every published freeze and add a separate fresh-rebuild verification workflow. Bind immutable raw source identifiers, stable adapter/model/policy/scorer identity, canonical logical inputs, and a deterministic semantic array digest independent of cache generation/container bytes. Retain generation byte hashes for checkpoint integrity. Emit a new receipt explicitly linked to the published comparison and compare numerical outputs/aggregates under a declared equality rule; do not pretend a new generation is the original archive or rewrite its historical hashes. Scope a resource estimate and single command from pinned public acquisition through report. Offline replay from originals and fresh reconstruction should be distinct supported operations.

This should be prioritized as reproducibility engineering after, or alongside, minimal packaging; it does not establish that any reported score is wrong. Root's independent score replay is the appropriate evidence for numerical correctness, outside this report's remit.

## 5. History limits some proposed research priorities

### Camera work was paused for an evidenced reason

`PROGRESS.md:25–38` records that the first pilot's 49 new assignments all came from restart-ambiguous rows, not missing-ball rescue. The controlled comparison later isolated the baseline confound: 13 raw new assignments, zero changed scorer-expanded labels, and none of 284 compared unresolved missing-tactical-ball rows had an observed broadcast ball (`:65–86`). Those counts cannot establish that broadcast is useless; they establish lack of usable evidence in this tested subset.

The later full automatic stage used fixed OCR settings and yielded zero usable alignment links (`PROGRESS.md:100–102`, `CHANGELOG.md:9`). `automatic_sync.py:298–333` actually performs discovery-based window selection/dense clock work; `AUTOMATIC_SYNC.md:13–19` explicitly keeps live/replay and fusion readiness false. The older manual options still exist in `multicam.py:327` and ROI source, but are not traversed by the selected tactical/neutral route.

The council's recommendation to defer broad OCR/fusion is **VALID**. Phrase it as an opportunity-cost decision given unsuccessful alignment and missing observation opportunities, not proof that more cameras cannot help. A useful future camera milestone would first validate automatic timing/live correspondence on external footage and show it delivers extra ball/state information; another framework layer or replay-shaped clock is not that evidence.

### “Obtain fresh H/A/D data” is necessary but not a trivial overlooked task

`docs/fresh-had-cohort-scout.md:3–5,20–24,38–52` records concrete near-fits and unresolved rights, semantics, access and non-overlap. `docs/accuracy-first/accuracy-reference-update.md:3–15` expands the search and concludes no qualified new full-state cohort. These are bounded documentation inspections, not proof that no usable source exists. They are also evidence that the team has already recognized the main validity bottleneck.

The independent-provider experiment was originally a genuine cross-provider attempt, then was rejected, and later analyses openly reused its matches. `TEMPORAL_RECOVERY.md:13–17` identifies the impossible confidence grid as a design error rather than declaring motion uninformative; the later analytic feasibility guard is already implemented (`docs/github-research-summary.md:5–9`). `TEMPORAL_RECOVERY.md:40–56` preserves last-owner/two-sided comparisons and failed precision/support gates. `docs/confidence-ablation.md:20–37` shows direct choices increased frame accuracy while hurting spellF1 and leaving large unmeasured areas. `ENSEMBLE_FINDINGS.md:5–17` shows agreement improved some seen-data scores but was not promoted as fresh validation.

Accordingly, “revive the old motion model,” “remove confidence,” “try endpoint carry,” and “add a feasibility check” are **PARTLY VALID only as new controlled hypotheses**, not untried immediate fixes. A strong current nearest-player-plus-window baseline, externally predeclared short-spell/hidden-event diagnostics and team-symmetry/observation-quality tests are genuinely useful next comparisons. Do not call the rejected motion experiment useless or assume symmetrizing the current head will improve scores before evaluation.

Fresh validation remains the highest scientific requirement. Make its next task concrete: resolve one candidate source's data/label rights and state ontology, establish temporal/team non-overlap, define annotation/adjudication if external labels must be created, and freeze access/analysis boundaries before seeing candidate outcomes. If rights/reference qualification cannot be completed, retain seen-data exploratory status and do structural/reproduction work without presenting it as new generalization evidence.

## 7. Concrete priority order

1. **Immediate, no predictor change:** repair audit manifest/omitted probe references; add a short route matrix identifying branch/commit, standalone vs checkout, policy/model identity, required inputs, output mode and experimental status. Fix stale standalone header and historical installer version contract or archive the latter explicitly. These are bounded correctness/documentation tasks.
2. **Scientific gate:** turn the already completed source scout into one concrete rights/reference qualification or external-annotation plan. Preserve current model and score receipts; stop treating further seen-data gains as independent evidence. The council's main evidence criticism survives the historical context.
3. **Independent of new data access:** preserve cheap structural/metamorphic probes, improve uncertainty/short-spell/hidden-change and corruption diagnostics, and add a fair simple nearest-team temporal comparator. Use the existing corpus only as named development/regression evidence. Do not repeat already completed confidence/endpoint experiments as if they were novel.
4. **Delivery milestone:** create a separate selected-only export and optional all-comparators mode, with exact selected-output parity and a measured resource report. Keep old bundle/source/research commands frozen. Packaging an exploratory candidate does not promote its scientific status.
5. **Reproduction milestone:** add a new-lineage public raw-to-report rebuild based on stable raw/semantic identity while retaining archive byte hashes for immutable historical replay. Test it in a fresh workspace rather than merely renaming an original-cache replay copy “clean.”
6. **Defer broad camera expansion:** require a successful externally validated timing/live-correspondence and extra-information milestone before another large OCR/fusion investment. Existing zero-link and no-secondary-ball evidence justifies this order; it does not rule out future automatic observation recovery.

The principal delivery criticisms hold, with sharper boundaries than repetition across six reviewers might suggest. The source contains a usable, deliberately preserved older standalone and a reproducible committed latest inference path; it does not contain a minimal latest export or a raw-data-only reconstruction of the latest sealed comparison. The strongest new concrete fixes from this historical review are the stale installer version gate, the random-generation-versus-byte-frozen replay mismatch, and the audit's own missing/misnamed artifacts and stale hashes.
